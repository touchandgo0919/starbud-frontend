AI Assistant Product Design v1.1

用数据解释变化，
把决定留给家长

AI 助手根据儿童的任务领取、完成、提交、提醒和批改记录生成趋势、周报与可执行建议。它不替代家长判断，不给儿童贴标签，也不把访问次数当作学习能力。

确定性优先完成率、延迟等指标由代码计算，模型只负责解释。
证据可追溯每条洞察必须引用日期范围、任务数和具体指标。
家长确认AI 只能生成任务草稿，不能直接修改孩子安排。
儿童友好儿童端只给下一步和鼓励，不展示风险、排名和预测。

V1 功能范围

先解决三个真实问题

第一版不分析 R2 中的照片和录音内容，先使用现有结构化数据建立可验证、成本可控的分析闭环。

01

家长看懂趋势

用近 7、28、90 天的任务数据解释完成规律、提醒效果和需要调整的时间段。

02

孩子知道下一步

小程序给出今天最合适先做的任务、简短说明和完成后的积极回顾。

03

建议能被执行

AI 根据证据生成任务时间、提醒次数或任务拆分草稿，由家长检查后保存。

市场参考与创新

学习助手正在从回答问题，转向组织学习过程

参考主流学习产品的有效模式，但不复制它们的通用聊天入口。星星芽的优势是已经连接家长安排、儿童执行、附件提交和真实批改。

KHANMIGO / CHATGPT STUDY

苏格拉底式引导

先问孩子卡在哪里，再逐步给提示、检查理解，不把最终答案作为第一响应。

DUOLINGO MAX

场景练习后反馈

AI 被放进具体练习场景，完成后评价准确性、复杂度并提出下一次建议。

NOTEBOOKLM

基于材料生成复习

测验、卡片和回答来自用户选择的资料，减少通用模型偏离学习内容。

GEMINI STUDY NOTEBOOKS

动态推荐下一步

根据诊断和练习结果推荐短课、测验与优先内容，持续更新学习路径。

星星芽的创新方向：AI 不成为第四个任务系统，而是作为一层能力嵌入任务创建、执行、提交、批改和家庭复盘；每次建议都能被验证、被否定、被撤回。

八个 AI 能力触点

P0 可以只使用现有结构化数据；P1 需要增加学科、学习目标或材料；P2 涉及照片和录音内容，必须单独授权。

提示阶梯

儿童点击“我卡住了”后依次获得澄清问题、小提示、相似例子和分步解释，默认不直接给完整答案。

把“问答案”改成“继续思考”
P0 · 批改时

家长评价草稿

根据任务说明、提交轮次和家长勾选的观察点，生成具体、积极的评价草稿，家长编辑后提交。

减少批改负担，保留家长声音
P1 · 复习

错题变微练习

同一任务多次重新提交时，基于家长提供的学习材料生成 3 分钟复习卡或 3 道小测。

内容必须可追溯到家庭材料
P1 · 复盘

亲子对话卡

每周从真实完成记录生成一个值得肯定的事实、一个开放问题和一个下周共同约定。

把数据转成沟通，不转成排名
P2 · 录音

朗读与口语教练

在家长授权后分析转写、停顿和任务要求，给孩子一个可执行的练习建议，并把原始录音保留策略交给家长。

不推断情绪、性格或心理状态
P2 · 图片

过程型作业提示

识别作业步骤并指出可能需要检查的位置，只给提示和验证方法，不替孩子完成整份作业。

低置信度必须明确提示家长复核

首屏只保留一个主动作，其他内容按紧急程度和认知负担排序。页面打开不实时调用模型，优先读取 D1 中每日分析快照，再与实时任务状态合并。

01 · 今日状态

问候与轻量进度

显示日期、今日任务数和已完成数。只做事实反馈，不展示完成率排名或综合评分。

02 · 必须处理

状态合并与额外提醒

待修改任务直接成为下一步，不再重复显示通知；只有另一项任务收到新批改时才增加轻量提醒。

03 · 核心动作

唯一“下一步”

按待修改、已领取、未领取、待批改顺序选择一项任务，显示原因和明确按钮。

04 · AI 支持

受控提示入口

仅对已领取且未完成任务开放“小提示”和“拆成步骤”，后续接入真正的提示阶梯接口。

05 · 正向回顾

一个真实进步

从近 7 天数据选择一条可验证事实；数据不足时显示普通鼓励，不伪造连续天数。

分析指标

模型看到什么，不看到什么

所有数值先由 Worker 通过 SQL 和 TypeScript 计算。模型接收聚合指标和匿名事件，不接收密码、用户名或家庭成员真实姓名。

指标计算方式可用于限制
任务完成率完成任务数 / 到期任务数观察整体执行趋势至少 7 项到期任务才生成结论
按时完成率完成时间不晚于计划时间 + 容差调整任务时间段一次性任务与重复任务分开统计
领取延迟claimed_at - 计划提醒时间判断启动困难和提醒效果不等同于拖延或态度
提交与批改轮次submission_review_rounds 数量识别需要拆分说明的任务不能直接推断学习能力
提醒有效性提醒后 15 分钟内领取的比例优化提醒时间与次数提醒上限仍为 3 次
家长反馈时延reviewed_at - submitted_at提示家庭协作阻塞作为流程指标，不归因于儿童
访问事件关键业务事件序列发现页面和流程问题禁止用于儿童表现评分

Cloudflare 架构

异步分析，结果版本化

请求与页面接口保持轻量，AI 分析由队列异步执行。模型失败不会影响任务、提交和提醒主流程。

SOURCED1 业务数据

任务、领取、提交、批改、提醒。

COMPUTEWorker 聚合器

计算指标、匿名化、生成 input hash。

ASYNCCloudflare Queue

削峰、重试，不阻塞用户请求。

MODELOpenAI Responses API

统一使用 gpt-5.5，严格 JSON 输出，不存储响应。

STORED1 分析结果

保存证据、模型和提示词版本。

处理流程

让模型不参与算数

指标与结论分开，既便于测试，也能在更换模型后保持历史数据口径一致。

  1. 触发分析

    每天凌晨生成增量分析；家长也可以手动刷新，每个儿童每小时最多一次。

  2. 确定性聚合

    Worker 查询 D1，生成 metric_id、数值、样本数、日期范围和对比周期。

  3. 隐私最小化

    用 child_ref 替代姓名；默认排除 R2 照片、音频、备注全文和访问日志正文。

  4. 模型生成结构化结论

    每条 observation 必须引用 metric_id；无足够样本时输出 insufficient_data。

  5. 规则校验

    JSON Schema、敏感词、诊断性语言、比较排名和直接执行动作全部在 Worker 中拦截。

  6. 家长确认

    建议可转换为任务草稿，家长编辑并保存后才进入原有任务系统。

API 设计

所有 AI 能力仍归 backend 管理

前端和小程序不直接持有模型密钥，也不能绕过家庭权限读取其他儿童的分析。

儿童数据安全

明确允许与禁止

AI Gateway 只保留调用元数据，敏感分析请求关闭 prompt 和 response 正文日志；个性化结果不使用共享缓存。

允许

  • 总结任务趋势并引用样本数和日期。
  • 建议调整任务时间、提醒次数或拆分步骤。
  • 说明数据不足并拒绝生成确定结论。
  • 为家长生成可编辑、未保存的任务草稿。
  • 为儿童提供当前任务说明和积极事实反馈。

禁止

  • 诊断 ADHD、焦虑、智力、人格或心理问题。
  • 给儿童打综合分、排名或与兄弟姐妹比较。
  • 仅根据访问频次判断学习态度或能力。
  • 未经家长确认自动新增、删除或调整任务。
  • 默认把照片、录音和备注全文发送给模型。

实施阶段

从可验证周报开始

先证明指标和建议确实有用，再扩大模型输入范围。不要第一版就做开放式 Agent。

Phase 1 · P0

首页洞察与小实验

先上线可追溯周报、任务表达助手、7 天家庭小实验和批改评价草稿，全部嵌入现有页面。

验收：建议可验证，操作需确认
Phase 2 · P1

学习过程支持

小程序增加提示阶梯、材料内微练习；家长首页增加每周亲子对话卡。

验收：默认不给完整答案，不做排名
Phase 3 · P2

可选多模态教练

在单独授权、脱敏和保留期限控制后，再增加朗读录音与作业图片的过程型反馈。

验收：默认关闭，可随时删除
